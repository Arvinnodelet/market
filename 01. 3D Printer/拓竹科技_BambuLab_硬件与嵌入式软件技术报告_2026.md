## 一、硬件方案

### 1. 整体硬件架构：三层分布式控制

Bambu Lab 采用**"AP + MC + TH"三层分布式硬件架构**，将计算任务按实时性要求分配至不同层级的处理器：

```
┌─────────────────────────────────────────────────┐
│                   AP 层（应用处理器）              │
│  Rockchip RV1126 / ESP32                        │
│  运行 Linux（X1/H2D）或 RTOS（P1/A1）            │
│  负责：G-code 解析、运动规划、UI、网络、摄像头、AI │
└──────────┬──────────────────────────────────────┘
           │ UART / SPI 高速串行
           ▼
┌─────────────────────────────────────────────────┐
│                  MC 层（运动控制器）               │
│  Spintrol SPC2168（双核 M4F @200MHz）            │
│  负责：X/Y/Z 轴实时步进脉冲生成、风扇控制           │
└──────────┬──────────────────────────────────────┘
           │ CAN / UART 总线
           ▼
┌─────────────────────────────────────────────────┐
│               TH 层（工具头控制器）                │
│  Spintrol SPC1168（单核 M4F @200MHz）            │
│  负责：挤出电机控制、热端温控、涡流传感器采样        │
└─────────────────────────────────────────────────┘
```

**设计理念**：将高实时性任务（步进脉冲、温控 PID）下沉至专用 MCU，将计算密集型任务（运动规划、AI 推理、GUI）上移至运行 Linux 的 AP。这与 Klipper 的 Host+MCU 思路同源，但 Bambu 使用自研 C/C++ 运动规划器替代了 Klipper 的 Python 宿主，实现了更高的控制带宽和更低的延迟。

### 2. 核心处理器与芯片选型

#### 2.1 AP（Application Processor）对比

| 机型系列 | AP 芯片 | 架构 | OS | 关键能力 |
|---------|---------|------|-----|---------|
| **X1C / X1E** | Rockchip RV1126 | Quad-core ARM Cortex-A7 + NPU (2.0 TOPS) | Linux 4.19 | AI 视觉检测、LiDAR 数据处理、5" 触屏 |
| **H2D / H2C** | 自研 NPU（未公开具体型号） | NPU + Linux AP | Linux | 2 TOPS 算力、喷嘴摄像头 AI、双路视频流 |
| **P1P / P1S** | Espressif ESP32 | Dual-core Xtensa LX6 @240MHz | FreeRTOS | 基础 UI、WiFi、简单逻辑 |
| **A1 / A1 mini / A2L** | Espressif ESP32 | Dual-core Xtensa LX6 @240MHz | FreeRTOS | WiFi、触摸屏 UI、PMSM 伺服控制 |

> ⚠️ **说明**：H2D 和 X1 系列的 AP SoC 具体型号未由官方完整披露。X1C 的 AP 确认为 Rockchip RV1126（基于开源合规披露的 Linux BSP）；H2D 的 NPU 型号未知。P1/A1 系列使用 ESP32 单一芯片方案，所有逻辑（包括 UI）均在 ESP32 上运行。

#### 2.2 MC（Motion Controller）—— Spintrol SPC2168

| 参数 | 规格 |
|------|------|
| CPU | **双核 ARM Cortex-M4F @200MHz** |
| FPU | 单精度硬件浮点（双核均配备） |
| Flash | 512 KB |
| SRAM | 80 KB（含 16 KB XIP Cache） |
| ADC | 14-bit、20 通道、140ns 转换时间、差分采样 |
| PGA | 6 路可编程增益放大器（1-64 倍） |
| 高速比较器 | 16 路 |
| PWM | 8 组增强型、16 路输出，所有事件可触发 ADC |
| 通信接口 | 4×UART、4×SPI、4×I²C、3×SIO（可配置为 CAN） |
| 封装 | LQFP-80 / LQFP-64 |

**选型逻辑**：SPC2168 是旋智电子（Spintrol，前 Fairchild 电机产品线）面向高性能电机控制的专用 MCU。其核心优势在于：
- **高精度 14-bit ADC + PGA 前放**：直接接入涡流传感器、热敏电阻等模拟信号，无需外置 ADC
- **硬件比较器 + PWM 联动**：步进电机失步检测、过流保护全硬件完成，延迟 < 100ns
- **双核架构**：主核跑运动插补，协核跑安全监控，实时性互相不干扰

#### 2.3 TH（Tool Head Controller）—— Spintrol SPC1168

| 参数 | 规格 |
|------|------|
| CPU | **单核 ARM Cortex-M4F @200MHz** |
| Flash | 128 KB |
| SRAM | 64 KB |
| ADC | 14-bit、16 通道 |
| PGA | 3 路 |
| 高速比较器 | 10 路（带数字去抖） |
| PWM | 6 组增强型、12 路输出 |
| 封装 | LQFP-48 / QFN-52 |

**选型逻辑**：SPC1168 是 SPC2168 的单核裁剪版，管脚更少、封装更小，适合工具头紧凑空间。固件可复用 SPC2168 的代码库。负责：
- PMSM 伺服挤出机 FOC 控制（20 kHz 电流环）
- 热端 PID 温控（双热端同步控制，H2D 系列）
- 涡流传感器高速采样与预处理
- 喷嘴摄像头数据转发（H2D）

#### 2.4 辅助芯片

| 芯片 | 用途 | 所在型号 |
|------|------|---------|
| **ESP32** | WiFi+BLE 通信模组 / 主控（P1/A1 系列） | 全系列 |
| **ESP32-S3** | 触摸屏驱动（A1/A2L 系列） | A1、A1 mini、A2L |
| **Rockchip RV1126** | AP 主处理器（含 2.0 TOPS NPU） | X1C、X1E |

#### 4.2 电机驱动器

Bambu Lab 使用**分立式 MOSFET 驱动 + SPC2168 硬件 PWM**方案，而非外置 TMC 驱动芯片。优势：
- 驱动波形完全由固件控制，可针对自家电机参数优化微步细分
- 14-bit ADC 实时采样相电流，硬件比较器做堵转保护
- 与 Spintrol MCU 深度绑定，PWM 事件可硬件触发 ADC 采样（零 CPU 开销）

#### 4.3 主动振动补偿（Active Vibration Compensation）

```
传统 Input Shaping：              Bambu 主动振动补偿：
手动打印测试件                     自传感器自动标定
      │                                │
      ▼                                ▼
肉眼判断振纹 → 手动输入频率       加速度计扫频 → 自动建模
      │                                │
      ▼                                ▼
固定频率 Shaper 滤波              自适应 Input Shaper + 源头轨迹优化
      │                                │
      ▼                                ▼
  仅消除残余振动              从源头避免振动产生 + 残余消除
```

- 加速度计在打印前自动执行扫频激励，测量全机共振频谱
- 固件自动选择最优 Shaper 类型和频率
- 运动规划器在轨迹生成阶段即规避共振频率区间的加减速模式

### 2. 实时运动控制

#### 2.1 运动规划管线

```
G-code 文本流
      │
      ▼
┌──────────────┐
│   解析器      │  ← 词法/语法解析，提取运动指令
└──────┬───────┘
       │ 内部运动指令序列
       ▼
┌──────────────┐
│  Lookahead   │  ← 前瞻缓冲区（深度未公开），分析拐角/加减速
│   轨迹优化    │     计算最优衔接速度，最小化 Jerk
└──────┬───────┘
       │ 时间参数化轨迹
       ▼
┌──────────────┐
│ 速度规划器   │  ← 梯形/S 形加减速轮廓生成
│              │     结合主动振动补偿约束
└──────┬───────┘
       │ 密集位置-时间点序列
       ▼
┌──────────────┐
│ 运动插补器   │  ← 运行于 SPC2168 MCU
│ (MC 层)     │     将位置点转为实时步进脉冲
└──────────────┘
```

#### 2.2 与 Klipper 的关键差异

| 维度 | Klipper | Bambu Lab |
|------|---------|-----------|
| 运动规划语言 | Python (Host) | **C/C++ (AP)** |
| 规划器位置 | 树莓派等单板机 | AP SoC（嵌入式） |
| 前瞻深度 | 固定（可配置） | **更长**（推测基于轨迹复杂性自适应） |
| 速度-压力联合控制 | ❌ 解耦（Pressure Advance 独立） | ✅ **联合优化**（速度变化同时预测压力需求） |
| 振动处理策略 | 事后消除（Input Shaper 滤波） | **源头避免 + 事后消除**（轨迹规划回避共振区 + Shaper） |
| 控制带宽 | 中（受 Python 调度抖动限制） | **高**（全 C/C++ 实现，零 GC 暂停） |
| 参数调校 | 用户手动（测共振、选 Shaper） | **全自动**（加速度计扫频 → 自动建模 → 自动配置） |

#### 2.3 关键控制参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 步进脉冲最高频率 | ~200 kHz（推测） | SPC2168 200MHz / 微步细分决定 |
| 温控 PID 频率 | ~10 Hz | 热端/热床温控循环 |
| 挤出电流环频率 | **20 kHz**（PMSM 伺服机） | 比步进电机开环快 100-1000 倍 |
| 涡流传感器采样 | kHz 级别（推测 >1kHz） | 用于实时压力测量 |
| 运动规划更新频率 | 100-1000 Hz | AP → MC 指令下发 |

#### 3.2 X1 系列标定差异

| 步骤 | X1 系列 | A1/H2D/P2S 系列 |
|------|---------|-----------------|

### 5. 通信协议栈

```
┌──────────────────────────────────────┐
│            应用协议层                  │
│                                      │
│  MQTT (云通信)     HTTP/HTTPS (文件) │
│  Bambu Connect    FTP (G-code 传输)  │
│  (切片→打印机)                       │
└──────────────┬───────────────────────┘
               │
┌──────────────┴───────────────────────┐
│          内部总线协议                  │
│                                      │
│  AP ←→ MC：自研串行协议               │
│  MC ←→ TH：CAN 总线 (1 Mbps)         │
│  TH ←→ AMS：CAN 总线                  │
│  TH ←→ 传感器：SPI / I²C             │
└──────────────────────────────────────┘
```

**CAN 总线优势**：
- 多节点仲裁、错误检测、差分信号抗干扰
- 实时性优于 UART（确定性延迟）
- 支持 AMS 多级串联（最多 4 台 AMS × 4 槽 = 16 色）
- 热插拔检测（AMS 即插即用）

### 6. 安全架构

#### 6.1 授权认证体系（2025 年引入）

```
┌──────────┐     ┌──────────────┐     ┌──────────┐
│ 第三方    │     │ Bambu Connect│     │ 打印机   │
│ 切片软件  │     │ (中间件)     │     │ 固件     │
│          │     │              │     │          │
│ OrcaSlicer│ ──→ │ 证书签名认证  │ ──→ │ 验证签名  │
│ (不支持) │     │ 双向 TLS     │     │ ✅/❌    │
└──────────┘     └──────────────┘     └──────────┘
                                           │
                                      MQTT 加密通道
```

- **Developer Mode**：可选关闭认证，接受所有指令（高级用户 / 局域网模式）
- 自固件 01.08.03.00 起，未经认证的 MQTT 指令直接拒绝

#### 6.2 安全启动（Secure Boot）（部分型号）

- X1/H2D 系列：AP 端验证 Linux 内核签名
- MCU 端：固件完整性校验（CRC / 签名）
- 防回滚：禁止安装低于最低版本的固件

#### 6.3 硬件安全

| 保护机制 | 实现方式 |
|---------|---------|
| 过温保护 | NTC + 硬件比较器（SPC2168），三级：限功率 → 暂停 → 断电 |
| 热失控保护 | 固件 + 硬件双冗余——固件检测温度上升速率，硬件直接比较器切断 |
| 电机堵转保护 | 相电流 ADC 采样 + 硬件过流比较器，延迟 < 100ns |
| 断电续打 | 电容储电 + 位置记忆，断电后手动恢复 |
| 电源异常保护 | 输入欠压/过压检测，PSU 自带保护 |

### 7. 健康管理系统（HMS）

HMS（Health Management System）是 Bambu Lab 的**分布式故障诊断与报警系统**：

#### 7.1 错误码结构

```
0300 — 1A00 — 0002 — 0001
  │      │      │      │
  │      │      │      └── 错误 ID（唯一故障算法标识）
  │      │      └───────── 严重等级（0001=错误, 0002=警告, 0003=通知）
  │      └──────────────── 子部件 ID + 编号
  └─────────────────────── 模块 ID（03=MC, 05=AP, 07=AMS, 08=TH, 0C=LiDAR）
```

#### 7.2 模块 ID 分配

| ID | 模块 | 职责 |
|----|------|------|
| 03 | MC | 运动控制器——电机、风扇、热床 |
| 05 | AP | 主板——网络、存储、摄像头 |
| 07 | AMS | 自动供料系统——耗材切换、RFID |
| 08 | TH | 工具头——热端、涡流传感器、挤出机 |
| 0C | XCAM | Micro LiDAR——首层扫描、流量校准 |
| 10 | Studio | Bambu Studio 切片软件端错误 |
| 11 | APP | Bambu Handy 移动端通知 |

#### 7.3 告警等级

| 级别 | 颜色 | 对打印的影响 |
|------|------|-------------|
| **0001 - 错误** | 🔴 红色 | **立即停止打印**，必须解除才能继续 |
| **0002 - 警告** | 🟡 黄色 | **暂停打印**，可解除后恢复 |
| **0003 - 通知** | 🔵 蓝色 | 仅信息提示，不影响打印 |

#### 7.4 HMS 架构特点

- **分布式探测**：每个子模块运行独立的状态检测器，不依赖中央轮询
- **即时推送**：错误发生后通过 MQTT 同时推送到屏幕 + App + Studio
- **QR 码引导**：错误页面生成 QR 码，扫码直达 Wiki 排障教程
- **局限性**：HMS 无法覆盖所有故障场景（如丢步的间接后果），根源分析能力有限

### 8. OTA 升级机制

| 特性 | 实现 |
|------|------|
| **升级通道** | WiFi OTA（默认）、microSD 离线、Bambu Studio 有线 |
| **固件分区** | 双分区 A/B 切换（X1/H2D 系列），升级失败自动回退 |
| **升级范围** | AP 固件 + MC 固件 + TH 固件 + AI 模型 + AMS 固件 |
| **回滚支持** | 支持手动降级（官方提供历史版本） |
| **升级验证** | 固件签名校验，防止篡改 |
| **安全保证** | 升级前检查打印状态（空闲才允许）、热端温度（<50°C）、电源稳定 |

**多 MCU 协同升级**：
一次 OTA 可能涉及 AP + MC + TH + AMS 四个固件的协同升级。升级流程为：
1. AP 先下载完整固件包（含所有子固件）
2. AP 升级自身 → 重启
3. AP 逐个向 MC → TH → AMS 推送新固件
4. 各子 MCU 本地校验后重启进入新版本
5. 全局版本一致性检查，不匹配则回滚

### 9. 开源/闭源策略

#### 9.1 开源部分（GPL 合规）

| 组件 | 许可证 | 说明 |
|------|--------|------|
| Linux Kernel 4.19 | GPL v2 | X1/H2D AP 端 |
| U-Boot | GPL v2 | 引导加载器 |
| Busybox / vsftpd / mosquitto 等 | 各类 GPL | 标准 Linux 用户态工具 |
| FreeRTOS | MIT | MCU 端 RTOS |
| **Bambu Studio** | **AGPL v3** | 切片软件（Fork 自 PrusaSlicer） |

#### 9.2 闭源部分

| 组件 | 原因 |
|------|------|
| 核心固件（运动控制、传感器融合、PID 算法） | 自研，无 GPL 依赖 |
| Bambu Connect（中间件） | 自研 |
| 云后端服务 | 自研 |
| ESP32 固件（P1/A1 系列） | 基于 Espressif SDK（非 GPL），无开源义务 |
| AI 模型文件 | 自研训练 |

#### 9.3 争议与现状

- **社区批评**：Bambu Studio (AGPL) 衍生的第三方切片软件（如 OrcaSlicer）被授权认证机制阻止直接通信
- **X1Plus 自定义固件**：社区开发的非破坏性固件覆盖层（SD 卡启动，不动 eMMC），Bambu 提供"放弃保修换自定义固件"的单向通道
- **核心立场**：Bambu Lab 合规地开源了 GPL 覆盖的组件，但将核心竞争力（运动控制、传感器融合、AI 推理）保留在闭源层，与消费电子行业的"合规开源+核心闭源"策略一致
