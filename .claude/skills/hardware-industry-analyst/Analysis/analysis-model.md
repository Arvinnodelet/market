# Analysis Model

## Purpose
将研究结果转化为可解释、可比较、可推演的分析。Framework 回答“查什么”，Analysis Model 回答“如何思考”。

## Universal Causal Chain
```text
Evidence
  ↓
Fact / Observation
  ↓
Mechanism / Cause
  ↓
Capability
  ↓
Product / User Effect
  ↓
Economic Effect
  ↓
Competitive Effect
  ↓
Strategic Significance
  ↓
Future Implication
```

不得从 Fact 直接跳到 Strategy，除非中间环节明确不适用并说明原因。

## Capability Test
当多个组件共同产生一个用户可感知结果时，将其定义为 System Capability，而不是多个孤立 Feature。

```text
Component → Subsystem → System Capability → Workflow Capability → Product Positioning
```

## Evidence-to-Conclusion Test
每个重要 Assessment 至少回答：
1. Evidence 是什么？
2. Mechanism 是什么？
3. 哪一步是 Inference？
4. 是否存在替代解释？
5. Confidence 是否与证据强度匹配？

## Competitive Defensibility Test
```text
Visible Feature
  ↓
Underlying Capability
  ↓
Complementary Assets
  ↓
Replication Difficulty
  ↓
Defensibility
```

Complementary assets 可包括 firmware、算法、数据、校准、制造工艺、供应链、软件生态、用户规模、组织能力。

## Trade-off Test
任何重大技术判断都要寻找：
- 性能收益
- 成本增加
- 结构/控制复杂度
- 可靠性风险
- 制造/校准负担
- 维护负担
- 适用边界

## Chapter Handoff
前章结论必须成为后章输入：

```text
Product Architecture
      ↓
Technology Capability
      ↓
Competitive Position
      ↓
Strategic Analysis
      ↓
Future Outlook
```

如果 Future Outlook 与前文技术/竞争分析没有明确连接，应视为质量缺陷。
